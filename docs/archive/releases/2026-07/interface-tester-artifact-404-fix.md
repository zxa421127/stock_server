# 市场接口测试台 internal_error / 下载404修复说明

## 现象

执行单接口测试后立即显示：

- `status = internal_error`
- `row_count = 0`
- `elapsed_ms = 0`

页面仍显示“完整JSON.gz / CSV.gz / 字段报告”，点击后返回“对应文件不存在”。

## 根因

结果存储的 gzip 原子写入逻辑在压缩文件关闭后，重新以只读模式打开临时文件并调用 `os.fsync()`。部分 Windows 运行环境会对只读文件描述符返回 `OSError: [Errno 22] Invalid argument`。

异常发生顺序为：

1. 上游调用结束；
2. `request.json` 开始写入；
3. `result.json.gz` 压缩完成；
4. 对只读句柄执行 `fsync` 抛出异常；
5. 项目被最外层安全网标为 `internal_error`；
6. 数据库未写入结果文件路径；
7. 前端无条件展示下载按钮，下载路由返回404。

同时存在一个独立问题：无数据时使用 `Path("")` 代表不存在的CSV，序列化后会变成 `.`，导致错误文件路径。

## 修复内容

1. gzip 文件在可写句柄关闭前执行 `flush + fsync`，兼容 Windows/Linux。
2. 空数据也按官方输出字段生成仅含表头的 `result.csv.gz`。
3. CSV不存在时使用 `None/空字符串`，不再保存为 `.`。
4. 新增 `storage_error` 状态，结果写入失败时保留异常类型和详情。
5. 未处理的数据转换异常会生成诊断JSON和字段报告，不再只留下空路径。
6. 页面直接显示 `error_code` 和 `error_message`。
7. 仅当数据库中存在对应文件路径时显示下载按钮。
8. 从未生成文件时下载接口返回409和执行错误；路径已记录但物理文件丢失时返回410。
9. 批量结果页同样按文件实际生成情况显示链接。

## 部署

本补丁基于“方案B：统一接口元数据、全量同步官方规格”代码。

1. 停止服务和外部接口测试 Worker。
2. 备份当前项目目录和数据库。
3. 将补丁目录内容覆盖到项目根目录，保持相对路径不变。
4. 删除项目中的 `__pycache__`（可选但建议）。
5. 重启 Web 服务和接口测试 Worker。
6. 重新执行 `tushare/etf_basic`。旧的失败项目不会自动补生成文件，需要重新测试。

不需要数据库结构迁移。

## 验收

使用 `etf_basic`、参数 `list_status=L` 执行真实上游测试：

- 上游成功：生成 JSON、CSV、字段报告和请求参数文件；
- 上游权限/参数错误：仍生成诊断 JSON、表头CSV、字段报告和请求参数文件；
- 存储层故障：页面显示 `storage_error` 和具体异常，不显示不存在的下载链接；
- 结果文件被人工删除：下载接口返回410，提示文件记录存在但物理文件已丢失。
